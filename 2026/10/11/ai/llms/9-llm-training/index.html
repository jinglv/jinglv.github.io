LLM 如何训练：从预训练到后训练

发表于 2026-10-11 分类于 大语言模型
从数据准备、反向传播和大规模预训练出发，理解继续预训练、SFT、偏好对齐、分布式训练、评测与迭代如何共同构成 LLM 的训练流程。

LLM 如何训练：从预训练到后训练

在上一篇文章中，我们进入 Transformer 内部，了解了 Token 如何经过 Embedding、Self-Attention、FFN 和多层 Transformer Block，最终得到词表上的 Logits。

不过，一个随机初始化的 Transformer 只会输出近似随机的概率分布。模型能够续写文本、回答问题、编写代码，并不是因为工程师把所有规则逐条写进程序，而是因为模型参数在大量训练数据上经过了持续优化。

本文将介绍一条典型的 LLM 训练路线：

目标与数据设计 → Tokenizer → 预训练 → 后训练 → 评测与安全验证 → 部署反馈与迭代

需要先说明：这不是所有模型都必须遵循的唯一流程。经典的 InstructGPT 路线包含 SFT、奖励模型和 PPO，但现代模型也可能使用 DPO、RLAIF、可验证奖励强化学习或其他后训练方法。不同团队会根据模型目标、数据和计算资源选择不同配方。

本文要回答什么？

本文重点建立训练全景，而不是教读者在一台电脑上复现前沿大模型：

  1. 训练过程中究竟在更新什么；
  2. 原始文本如何变成监督信号；
  3. 预训练、继续预训练和 SFT 有什么区别；
  4. 偏好数据、奖励模型、PPO 和 DPO 分别解决什么问题；
  5. 为什么训练大模型需要混合精度和分布式并行；
  6. 为什么 Loss 下降不等于模型已经安全、真实且可部署；
  7. 数据、训练、评测和部署反馈如何形成闭环。

核心概念

预训练：获得基础能力

预训练通常使用大规模文本、代码和多语言数据，通过自监督学习让模型掌握语言规律、知识关联及部分推理模式。

对于典型的 Decoder-only 自回归语言模型，训练目标是：给定前面的 Token，预测下一个 Token。原始文本本身就能提供输入和目标，不需要人工逐条标注，因此被称为自监督学习。

预训练完成后得到的通常称为基础模型（Base Model）。它擅长文本续写，但未必能稳定理解聊天角色、遵循用户指令或拒绝不安全请求。

监督微调：学习遵循指令

监督微调（Supervised Fine-Tuning，SFT）使用高质量的“指令—回答”或多轮对话数据继续训练基础模型，使它学会按照指定格式回答问题、完成任务。

SFT 的关键不只是数据数量，更是数据质量、覆盖范围和一致性。少量高质量数据可以显著改变模型的交互方式，但“5K～100K 条就一定足够”并不是普遍规律：所需规模取决于基础模型能力、任务范围、数据多样性和训练目标。

在常见的 assistant-only 训练方式中，系统消息和用户指令对应的标签会被设为 -100，只在 Assistant 回答部分计算交叉熵损失。不过，这同样不是硬性规定；有些训练配方会对完整序列计算损失，或者给不同部分设置不同权重。

偏好对齐：让回答更符合目标

SFT 告诉模型“一个合格回答是什么样”，偏好对齐则利用回答之间的相对优劣，进一步优化有用性、真实性、风格和安全边界。

偏好对齐有多种实现方式，RLHF 只是其中一种。因此，“预训练、SFT 和 RLHF 三个阶段缺一不可”并不准确。更稳妥的说法是：

  • 预训练通常负责获得通用语言能力；
  • SFT 常用于建立指令遵循和对话格式；
  • RLHF、DPO 等方法可以继续优化偏好，但具体路线因模型而异。

此外，完成偏好优化并不意味着模型已经“安全”或“完全符合人类价值”。训练数据的偏差、奖励模型的局限、越狱攻击和分布外输入仍可能导致失败，因此还需要持续评测、红队测试和部署期防护。

技术细节

1. 数据准备

训练前通常需要完成以下工作：

  1. 采集：收集网页、书籍、论文、代码和多语言语料等数据。
  2. 清洗：删除乱码、模板页、低质量内容和异常样本。
  3. 去重：减少重复文档和近似内容，降低记忆与数据泄漏风险。
  4. 过滤：处理隐私、版权、安全和基准测试污染等问题。
  5. 配比：控制不同语言、领域和数据来源所占比例。
  6. 分词：使用 Tokenizer 将文本编码为 Token ID 序列。

数据质量会直接影响模型能力上限。仅仅增加未经筛选的数据，不一定能持续提升模型效果。

继续训练还要注意灾难性遗忘：如果只使用范围很窄的新数据，模型原有的通用能力可能下降。因此常见做法包括混入部分通用数据、控制学习率，并持续评测多个能力维度。

2.4 如何理解训练规模

LLM 的训练规模差异非常大，不能用一组数字概括所有模型。下面是用于建立直觉的宽泛范围，而不是行业门槛：

项目 可能的量级 说明
训练数据 数十亿到数万亿 Token 取决于模型规模、数据策略和重复训练轮数
参数量 数亿到数千亿以上 小模型和超大模型的计算需求差异巨大
训练时间 数天到数月 取决于硬件数量、利用率和训练规模
训练成本 差异可达多个数量级 硬件、能源、工程和实验成本都应计入

因此，“7B～1T 参数”“几万亿 Token”“百万～亿美元”可以描述部分大型项目，却不应写成 LLM 训练的固定范围。

3. 监督微调（SFT）

SFT 数据通常包含：

  • 系统消息：规定模型角色、行为边界或输出格式；
  • 用户消息：提出指令或问题；
  • Assistant 消息：给出目标回答；
  • 多轮历史：让模型学习在对话上下文中持续交互。

训练过程依然是 Token 级交叉熵优化。与预训练相比，核心变化主要在于数据分布和标签掩码：模型不再只学习任意文本的延续方式，而是重点学习如何生成理想回答。

需要注意，聊天模板是模型训练格式的一部分。system、user、assistant 等角色最终都会被转换成特定的 Token 序列；推理时如果使用了不匹配的模板，模型表现可能明显下降。

4. 经典 RLHF：奖励模型与 PPO

RLHF（Reinforcement Learning from Human Feedback）利用人类反馈构造奖励信号。以经典的 InstructGPT 路线为例，它通常建立在已经完成 SFT 的模型之上。

4.3 使用 PPO 优化策略模型

PPO 阶段通常包含四个角色：

组件 作用
策略模型（Policy） 生成回答，也是要被更新的 LLM
参考模型（Reference） 通常冻结，用于限制策略偏离原有模型太远
奖励模型（Reward Model） 对完整回答给出奖励分数
价值模型（Value Model） 估计期望回报，帮助计算 Advantage

一个训练批次的简化流程如下：

  1. 策略模型根据 Prompt 采样回答；
  2. 奖励模型对回答打分；
  3. 计算策略模型与参考模型之间的 KL 惩罚；
  4. 价值模型估计回报，并计算 Advantage；
  5. 使用 PPO 的裁剪目标更新策略模型；
  6. 更新价值模型，并监控奖励、KL、长度和生成质量。

KL 约束用于减少策略模型为了追逐奖励而过度偏离参考模型的风险，但它不能彻底消除奖励投机或训练不稳定。

5. DPO 与 RLAIF

5.1 DPO：直接使用偏好数据

DPO（Direct Preference Optimization）直接在 chosen/rejected 偏好对上优化策略模型，不需要单独训练奖励模型，也不需要运行 PPO 的在线采样循环。

DPO 的工程实现通常更简单，但“更简单”不等于在所有任务上都与 PPO 效果相同。最终表现仍取决于偏好数据质量、参考模型、超参数和评测目标。

5.2 RLAIF：反馈来源发生变化

RLAIF（Reinforcement Learning from AI Feedback）使用 AI 生成或判断偏好反馈，以减少部分人工标注成本。它描述的是反馈来源，而不是一种与 PPO、DPO 并列的固定优化算法。

例如，AI 可以依据一组原则比较两个回答，再用这些偏好训练奖励模型或执行直接偏好优化。AI 反馈可以扩展数据规模，但也可能继承评审模型的偏差和错误，因此仍需人工校准和独立评测。

6. 各阶段对比

阶段 典型数据 优化目标 典型产物
预训练 大规模原始语料 下一个 Token 预测 基础模型
SFT 指令—回答、多轮对话 模仿目标回答、学习指令遵循 指令模型

7. 大规模训练为什么需要分布式系统？

当模型、Optimizer State、梯度和激活值无法放入单张 GPU 时，需要把计算或数据拆到多张设备上。

并行方式 基本思想 主要解决的问题
Data Parallel 每张设备放模型副本，处理不同数据 提高数据吞吐
Tensor Parallel 把单个矩阵运算拆到多张设备 单层参数或计算过大
Pipeline Parallel 把不同模型层放到不同设备 模型层整体放不下
Sequence Parallel 沿序列维度拆分部分计算 长序列激活占用大
Expert Parallel 把不同 MoE Expert 分散到设备 稀疏专家模型训练

大型训练还会使用：

  • BF16 或 FP16 混合精度；
  • Gradient Checkpointing，用额外计算换激活显存；
  • ZeRO 或 Fully Sharded Data Parallel，切分参数、梯度和优化器状态；
  • 高吞吐数据管线；
  • 分布式 Checkpoint；
  • 故障检测与训练恢复；
  • 通信与计算重叠。

因此，训练成本不只是“GPU 数量 × 运行时间”。硬件利用率、网络互联、存储吞吐和系统稳定性都会显著影响最终成本。

8. 评测为什么贯穿全流程？

Loss 是重要信号，但不是最终产品质量的完整度量。

不同阶段需要观察不同指标：

阶段 常见检查内容
数据准备 数据质量、重复率、隐私、版权、污染
预训练 Train/Validation Loss、Perplexity、能力评测
SFT 指令遵循、格式、领域任务、多轮对话
偏好优化 Win Rate、奖励、KL、长度偏差、Reward Hacking
安全评测 有害请求、越狱、隐私泄露、偏见
部署评测 延迟、吞吐、成本、稳定性、线上失败案例

评测集必须与训练数据隔离。若基准题目或参考答案进入训练集，分数可能反映记忆或数据污染，而不是真实泛化能力。

常见误区

误区一：LLM 训练固定分成三个缺一不可的阶段

预训练、SFT、奖励模型和 PPO 是一条经典路线，但并不是唯一配方。DPO 可以跳过显式奖励模型与 PPO；RLAIF 改变反馈来源；有些领域模型只进行继续预训练和 SFT。

误区二：只有 RLHF 才能提高安全性

安全数据 SFT、拒绝采样、DPO、规则系统、输入输出审核和部署期监控都可能参与安全治理。RLHF 不是安全性的充分条件，也不是唯一手段。

误区三：SFT 永远只在回答部分计算损失

只训练 Assistant Token 是常见实践，但不是定义本身。是否屏蔽 Prompt、是否训练多轮中的全部 Assistant 回复，以及是否对不同 Token 加权，都属于具体训练配方。

误区四：偏好标签代表统一的人类价值

不同人群可能对正确性、风格和安全边界有不同判断。所谓“人类偏好”实际上来自特定标注规范、标注者和采样分布，因此必须报告数据来源并进行偏差评测。

误区五：训练就是把资料存进模型

训练通过梯度更新分布式参数，使目标 Token 在相应上下文中获得更高概率。它不是把文档保存成可精确查询、实时更新的数据库。

误区六：训练 Loss 越低，模型就一定越好

更低的训练 Loss 可能来自更好学习，也可能伴随过拟合、数据泄漏或基准污染。模型还需要在独立验证集、下游能力、安全性和部署指标上评测。

误区七：模型参数显存就是全部训练显存

训练还需要梯度、优化器状态、激活值和临时工作区。使用 AdamW 全参数训练时，训练内存通常显著高于只加载权重进行推理。

误区八：微调一定能增加新知识

SFT 更擅长塑造回答格式和行为。注入大量稳定领域知识时，继续预训练、RAG 或外部工具可能更合适，具体取决于知识是否频繁变化、是否需要引用和能否容忍参数记忆误差。

小结

LLM 训练可以分成两个大的层次：

  1. 预训练：通过大规模自监督学习获得通用语言能力，产出基础模型；
  2. 后训练：通过 SFT、偏好优化及其他方法塑造模型行为，产出适合交互和部署的模型。

其中，SFT、RLHF、DPO 和 RLAIF 并不是互相完全排斥或固定依次出现的步骤，而是后训练工具箱中的不同组成部分。理解每种方法解决什么问题、使用什么数据、优化什么目标，比记住一条固定流程更重要。

还需要记住：训练是由数据、优化、分布式系统和评测共同构成的工程闭环。能够完成一次 loss.backward()，距离训练出可靠、可部署的大模型仍然很远。
